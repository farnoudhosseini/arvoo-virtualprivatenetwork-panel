Infrastructure you can audit.

Arvoo designs, deploys and operates compute, hosting and private connectivity. Every change is planned, applied, verified and written to an audit log — so capacity, access and routing are facts you can check, not promises.

What we run

  • Cloud compute

    Virtual servers and dedicated machines sized to the workload, with storage, snapshots and capacity agreed before it is needed.

  • Managed hosting

    Application, database and web hosting that we operate end to end: OS patching, backups with tested restores, monitoring and on-call response.

  • Private connectivity

    Encrypted links between your sites and our regions, so application traffic never depends on the public internet. Reachability is measured, not assumed.

  • Access and identity

    Per-user access to the management plane, defined roles, session lifetimes, strong transport security and an immutable record of who changed what.

  • Domains and DNS

    Registration, authoritative DNS and certificate lifecycle for the names your services answer on, including automatic renewal that we monitor.

  • Operations and support

    Monitoring, alerting, capacity planning and incident handling, with direct contact to the engineers who operate the platform.

How the platform is operated

  1. Planned and applied

    You describe the desired state in the panel or the CLI; the system validates it, prepares it, applies it, verifies it on the host and only then records it as done.

  2. Verified, not assumed

    Deployments read the real state of the machine back — services, addresses, routes, certificates, processes — and report the actual result, including failure.

  3. Recoverable

    Changes that fail are rolled back with a visible report. Backups are taken before risky operations and a restore is rehearsed, not hoped for.

  4. Audited

    Authentication, privilege changes, deployments and credential rotation are logged with actor, time and outcome. Secrets are never written to those logs.

Continuity

The platform is built to keep running when parts are unavailable: maintenance work queues and retries, a lost host reconnects and re-synchronises, and the terminal tools keep working when the panel is down.

Where we operate

Arvoo deployments are single-tenant: capacity, region and connectivity are agreed per engagement, and we confirm what is available before a contract rather than publishing a generic map. Tell us where your users and offices are and we will propose a topology.

Service status

Status is not decorative here. Customers receive the live health endpoint of their own deployment, so availability is read from the same system that runs their services — not from a separate page that can disagree with reality.

Already a customer? Check your deployment's health from the panel or run: 

arvoo health

Documentation

Installation is one command on Ubuntu 24.04, and the same installer repairs, updates, backs up and diagnoses an existing deployment. The command-line tools mirror the panel, so an outage in the web interface never blocks operations.

Deploy

sudo ./install.sh
# 1 Master / Panel   2 Node Agent
# 3 Repair   4 Update
# 5 Diagnostics   6 Uninstall

Operate

arvoo status
arvoo diagnostics
arvoo logs --component master --follow
arvoo backup   /   arvoo restore --file …

Secure

arvoo secret rotate
arvoo cert status
arvoo security-audit
arvoo management status
